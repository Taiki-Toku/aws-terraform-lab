CHAPTER 07｜設計・設定

アカウントとプラットフォーム

アカウントは「管理したい鍵1本1本」、プラットフォームは「その鍵の取扱説明書」です。取扱説明書を正しく選べば、CPMとPSMが正しく動きます。

2. プラットフォームとは

家電の「取扱説明書」

同じ「電源を入れる」でも、テレビと洗濯機では手順が違います。CPMやPSMも、Windowsのローカル管理者とOracleのSYSでは、パスワードの変え方・接続の仕方が違います。プラットフォームは、ターゲットの種類ごとの取扱説明書です。

CyberArkには、Windows・Unix/Linux・データベース・ネットワーク機器・クラウドなど、多数のプラットフォームのテンプレートが用意されています。足りないものは公式マーケットプレイス等のプラグインや、独自開発（プラグインの作成）で追加できます。

主な設定項目

設定カテゴリ代表的な設定
自動パスワード管理定期変更の間隔、定期検証の間隔、不一致時に自動で調整（Reconcile）するか、変更時刻の制限（業務時間外のみ等）
パスワードポリシー長さ、大文字・小文字・数字・記号の最低数、使用禁止文字（ターゲットが受け付けない記号の除外）
接続コンポーネントPSM経由で使う接続方式（RDP、SSH、SQLクライアント、Webアプリ等）と、使用するPSMサーバ
ポリシーの例外Master Policyの設定をこのプラットフォームだけ変更（例：本番DBだけ二重承認）
プラグイン固有の設定接続ポート、プロンプト文字列、タイムアウトなど
既定プラットフォームは直接いじらず「複製」して使う

標準テンプレートを直接変更すると、どこを変えたか分からなくなり、バージョンアップ時の比較も困難になります。「複製 → 自社用の名前を付ける → 変更」が鉄則です。名前に用途を入れておく（例：HK-Win-Local-PRD）と、棚卸しや調査が楽になります。

パスワードポリシーとターゲットの不一致に注意

ターゲットが受け付けない記号や長さをCPMが生成すると、変更が失敗します。例えば一部のネットワーク機器やアプリでは特定の記号が使えません。プラットフォームの「使用禁止文字」で除外しましょう。

3. 連携アカウント（Linked Accounts）

🚪 Logon Account（ログオン用）

対象アカウントで直接ログインできないときに使う「入口用」のアカウント。

例：hk-web01 は PermitRootLogin no（rootでの直接SSH禁止）。CPMは一般ユーザー opsadmin でログインし、そこから su でrootになってパスワードを変更する。

🛠 Reconcile Account（調整用）

対象アカウントのパスワードがVaultと食い違ったときに、強制的にリセットするための高権限アカウント。

例：Windowsドメインアカウントの調整には、パスワードリセット権限を持つ専用のドメインアカウントを使う。Linuxでは調整用の管理者アカウント（sudo可能）を使う。

調整用アカウント自体もCyberArkで管理する

Reconcile Accountは強い権限を持つため、それ自体もSafeに格納してCPMで管理します。ただし「調整用アカウントのパスワードが不一致になると調整できない」ので、専用Safe・厳格な権限・監視を設けます。

4. 依存先（Usages / Dependencies）

Windowsのサービス、スケジュールタスク、IISのアプリケーションプール、設定ファイルなどが、ある特権アカウントのパスワードを使っている場合があります。パスワードだけ変えると、それらが起動できなくなり障害になります。

CyberArkでは、こうした使用箇所を依存先として登録し、CPMがパスワード変更時に併せて更新できます。導入前の調査（どのサービスがどのアカウントで動いているか）が重要です。

Self-Hosted と Privilege Cloud の違い（この章のポイント）

🏢 Self-Hosted の場合

  • プラットフォームとCPMプラグインを自社のCPMサーバで管理
  • プラグインの改修・追加も自社環境で実施

☁ Privilege Cloud の場合

  • プラットフォームの考え方は同じ
  • Secrets Rotation Service では、プラグインはCPMと同じものをサービス側で一元管理し、エージェントにはキャッシュが配られる
  • ローカルでプラグインを編集しても反映はキャッシュのみ。恒久化するにはテクニカルサポートへ送付してバックエンドを更新してもらう
  • Secrets Rotation Service はプラットフォームグループ・ローテーショングループに未対応（制限事項）

出典（2026-10-19確認）：Secrets Rotation Service architecture、Secrets Rotation limitations and behavior changes

振り返り問題（第7章）

Q1. rootでの直接SSHが禁止されたLinuxで、CPMがrootのパスワードを変更するために必要なのは？

  • Reconcile Accountのみ
  • Masterユーザー
  • Logon Account（一般ユーザーでログインしてからrootに切り替える）
  • PSM for SSHの録画設定
Logon Accountで入ってからsu等で切り替えて変更します。

Q2. 標準プラットフォームを使うときの推奨手順は？

  • 複製して自社用の名前を付けてから変更する
  • 標準のものを直接編集する
  • 使わずに毎回新規作成する
  • Masterユーザーで編集する
複製してから変更することで、変更点の管理やバージョンアップ時の比較が容易になります。

Q3. Windowsサービスの実行アカウントのパスワードをCPMで変更した直後、サービスが起動しなくなった。最も疑わしい原因は？

  • Vaultのポート1858が閉じている
  • PSMの録画容量不足
  • Safe名が長すぎる
  • 依存先（サービス）が登録されておらず、サービス側のパスワードが更新されていない
依存先を登録してCPMに併せて更新させる必要があります。導入前の依存先調査が重要です。

Q4. アカウント登録直後にCPMでパスワード変更を行う主な目的は？

  • Vaultの容量を節約するため
  • 人が知っている古いパスワードを無効化し、確実に管理下に入れるため
  • 録画を開始するため
  • ライセンスを有効化するため
登録時点のパスワードは多くの人が知っている可能性があります。変更して初めて統制が効きます。
