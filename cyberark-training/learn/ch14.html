ZSP/JITとモダンアクセス

「強い権限を持ったアカウントを金庫で守る」から一歩進んで、「そもそも強い権限を常に持たせておかない」へ。クラウド時代の特権アクセスの考え方と、それを実現する製品を学びます。

1. 常設特権・JIT・ZSP

会議室の使い方で考える

常設特権：あなた専用の会議室の合鍵を常に持っている。使っていない夜中でも、鍵を落とせば誰でも入れる。
JIT（ジャストインタイム）：会議の時間だけ受付で鍵を借りる。ただし借りた鍵は全会議室共通のマスターキーかもしれない。
ZSP（ゼロ・スタンディング特権）：会議のたびに「その部屋の、その時間だけ開く」専用の鍵がその場で作られ、終わったら消える。普段は誰も鍵を持っていない。

方式権限を持っている時間権限の範囲盗まれたときの被害
常設特権常に広いことが多い最大
JIT必要なときだけあらかじめ用意された権限（広い場合もある）時間的に限定
ZSPセッションの間だけそのタスクに必要な最小限（その場で作成・終了後に削除）時間的にも範囲的にも限定
⏱

ZSP＝「必要なときに・必要なだけ・必要な間だけ」。終わったら権限そのものが消える。

攻撃者が狙う「放置された強い権限」そのものをなくすのが狙いです。

2. Secure Infrastructure Access（SIA）

SIA（2024年10月に Dynamic Privileged Access から改称。改称時に、ZSPに加えてVaultに格納した資格情報での接続にも対応）は、Windows／Linuxサーバ、データベース、Kubernetesなどへの特権アクセスを、JIT・ZSPの考え方で提供するSaaSです。

  • VPN・踏み台が不要：顧客ネットワーク内のコネクタが外向きに接続する方式で、インバウンドの穴を開けずに利用できる
  • 一時的な資格情報：セッションごとに短命な資格情報（一時的なユーザー・証明書など）を用意し、終了後に無効化
  • ネイティブクライアント：利用者は普段のSSHクライアント・RDPクライアント・DBクライアントで接続できる
  • 属性ベースのポリシー：クラウドのタグやネットワーク範囲などの属性で「誰が・どこに・いつ」アクセスできるかを定義
  • セッションの記録・監査：プラットフォーム共通の監査に記録
一時的な資格情報の方式（公式ドキュメント 2026-10-19 確認）

Linuxでは短命のSSH証明書（接続ごとに新しく発行され、数分で無効化）、Windows（RDP）では一時的なローカルユーザーまたはドメインユーザー、データベースではエンジンに応じて一時的なローカル／ドメインユーザーやRDSのIAM資格情報が使われます。セッション終了時や、無操作・時間帯・セッション時間などのポリシー制限に達した時点でアクセスが取り除かれます。詳細は設計時に対象ごとの公式手順で確認してください。

3. Secure Cloud Access（SCA）

SCAは、AWS・Azure・GCPなどのクラウド管理コンソールやCLIへの特権を、必要な時間だけ付与するSaaSです。

  • 常設の強いクラウドロール（管理者ロール等）を利用者に割り当てておかない
  • 利用者は必要なときに申請し、ポリシー（必要なら承認）に基づいて期間限定でロールが付与される
  • 期間が終わると自動で剥奪される

4. Endpoint Privilege Manager（EPM）

社用車の「スペアキー」を全員に配らない

PCのローカル管理者権限は、社員全員に社用車のスペアキーを配るようなものです。便利ですが、マルウェアも同じ権限で動けてしまいます。EPMはスペアキーを回収し、「このアプリのインストールだけ」「この設定変更だけ」をその場で許可します。

機能内容
最小権限（特権の除去と昇格）ローカル管理者権限を取り除き、ポリシーで許可したアプリ・操作だけ昇格させる。必要に応じて申請→一時的な昇格（JIT）
アプリケーション制御許可・ブロック・制限付き実行など、アプリごとに実行を制御
資格情報窃取対策OSやブラウザ等に保存された資格情報を狙う窃取の試みを検知・ブロック
ランサムウェア対策不審なファイル暗号化等の振る舞いからの保護

EPMは現在SaaSで提供され、Windows・macOS・Linuxに対応しています（対応OSは公式ドキュメントで確認）。公式のEnd of Life Policyによると、オンプレミス版は2021年1月6日に段階的終了が告知され、2023年12月31日でサポートが終了しています（2026-10-19確認）。

5. Remote Access（委託先アクセス）

  • 保守委託先（例：ネクスト保守サービスの小林さん）が、VPNなしで必要なシステムにだけアクセスできる
  • 委託先の担当者ごとにADアカウントやVPNアカウントを作らずに済む（JITでの登録）
  • モバイルアプリ（旧Aleroアプリ。現在はIdira Mobileアプリ）でワンタイムのQRコードを読み取り、顔・指紋認証で本人確認（生体情報はスマートフォン内に留まる）。Remote Accessは2021年にAleroから改称
  • アクセスはPSM等を経由するため、パスワードは渡さず、操作は録画される

6. Vault型PAMとZSP型をどう組み合わせるか

対象向いている方式理由
ネットワーク機器、古いOS、パッケージ製品の管理者Vault型（PAM＋CPM＋PSM）一時ユーザーを作れない・固定の管理者アカウントが必要なものが多い
緊急用アカウント（ブレークグラス）、ドメイン管理者Vault型（厳格なワークフロー）どうしても常設が必要なものは金庫で守る
クラウド上のLinux/Windows、DB、KubernetesZSP型（SIA）動的に増減し、属性で制御しやすい
クラウド管理コンソールZSP/JIT型（SCA）ロールの一時付与で常設特権をなくせる
社員PCのローカル管理者EPM端末の権限そのものを最小化
「どちらか」ではなく「両方」

現実の企業には古いシステムとクラウドが混在します。常設が避けられないものはVaultで守り、なくせる常設特権はZSPでなくす——これが現在の設計の主流の考え方です。

振り返り問題（第14章）

Q1. ZSP（ゼロ・スタンディング特権）の説明として最も適切なのは？

  • 全員に常に管理者権限を与える
  • 管理者パスワードを長くする
  • 必要なときにタスクに必要な最小限の権限をその場で作り、終了後に削除する
  • 特権アカウントをExcelで管理する
常設の特権をなくし、セッション単位で最小権限を付与・削除します。

Q2. AWS管理コンソールの管理者ロールを、必要な時間だけ付与したい。適切な製品は？

  • SCA（Secure Cloud Access）
  • EPM
  • CCP
  • PSM for SSH
SCAはクラウドのロールを期間限定で付与します。

Q3. 社員PCのローカル管理者権限を取り除き、特定アプリのインストールだけ昇格させたい。適切な製品は？

  • SIA
  • Secrets Hub
  • Remote Access
  • EPM（Endpoint Privilege Manager）
EPMは端末のローカル管理者権限を最小化する製品です。

Q4. Vault型PAMで守るのが向いている対象は？

  • オートスケールで増減するクラウド上のLinuxサーバ
  • 一時ユーザーを作れない古いネットワーク機器の管理者アカウント
  • Kubernetesのワークロード
  • クラウドの管理コンソール
固定の管理者アカウントが必要な機器は、Vaultに格納してCPM・PSMで守ります。
