CHAPTER 10｜利用・監視

PSMによるセッション管理

PSMは「付き添い付きの作業部屋」です。利用者は部屋の中から作業し、鍵（パスワード）は付き添い役が開けてくれます。部屋の中はすべて録画されます。

この章の全体像

PSMが提供する3つの価値 → 接続の内部フロー（PSMConnect・シャドウユーザー）→ 接続方法の種類 → PSM for SSH → 監視・録画の運用 → よくあるトラブル

この章のゴール

  • PSMの「分離・監視・記録」の価値を説明できる
  • Connectを押してからターゲットに入るまでの内部の流れを説明できる
  • PVWA・HTML5 Gateway・ネイティブクライアント・SSHなど接続方法の違いを説明できる
目安 80分前提：第3・6・9章重点章

1. PSMの3つの価値

銀行の「貸金庫閲覧室」

貸金庫の中身を確認するとき、お客様は行員に付き添われてガラス張りの閲覧室に入ります。箱を開けるのは行員（パスワードはお客様に渡らない）、部屋には防犯カメラ（録画）、不審な動きがあれば警備員がすぐ止められます（監視・切断）。

🧱 分離（Isolation）

利用者のPCとターゲットが直接つながらない。パスワードは利用者PCに渡らないため、利用者PCがマルウェアに感染していても資格情報を盗まれにくい。

👁 監視（Monitoring）

監査担当がセッションをリアルタイムで見られる。危険な操作を見つけたら一時停止・強制切断できる。

🎥 記録（Recording）

画面の録画と、キーストローク・SSHコマンド・SQL等の操作ログを保存。操作ログから録画の該当箇所へジャンプして確認できる。

2. 接続の内部フロー（Windows／RDP系）

PSMAdminConnectとは

PSMサーバには、受付用のPSMConnectのほかに、監査担当がライブセッションを監視するときに使われるPSMAdminConnectというアカウントもあります。どちらもPSMの内部用アカウントで、パスワードはCyberArkで管理します。期限切れ・ロックはPSMの接続障害の典型原因です。

3. 接続方法の種類

方法概要向いている人
PVWAから接続（RDPファイル）PVWAで「Connect」→RDPファイルが開き、PCのRDPクライアントでPSMへ接続標準的な利用者
HTML5 GatewayRDPクライアント不要。ブラウザのタブ内でセッションを開くRDPクライアントを使えない端末、委託先
ネイティブRDPクライアント（PSM for Windows）PVWAを開かず、使い慣れたRDPクライアントからPSM経由で接続多数のサーバを操作する管理者
SSHクライアント（PSM for SSH）普段使うSSHクライアントからPSM for SSHへ接続Linux管理者
Webアプリ・DBクライアントPSM上でブラウザやSQLクライアントを起動して接続（接続コンポーネントで定義）SaaS管理画面・DB管理者

4. PSM for SSH

PSM for SSH（PSMP）は、SSH接続を中継・記録するLinux上のコンポーネントです。利用者は普段のSSHクライアントのまま、接続先の指定方法だけ変えます。

# 書式の例：<Vaultユーザー>@<ターゲットのユーザー>@<ターゲットのアドレス>@<PSM for SSHのアドレス>
ssh a.takahashi@root@hk-web01.hikari.example@hk-psmp01.hikari.example

実際の書式（区切り文字、ドメインの指定方法など）は環境とバージョンにより異なります。ヒカリ精機では運用手順書に記載しています。

SSHでは「コマンド」が記録される

PSM for SSHでは、入力したコマンドがテキストで記録されるため、「誰が・いつ・どのサーバで rm -rf を打ったか」を検索できます。危険なコマンドの実行を検知・制限する仕組みと組み合わせることもできます。

5. 監視・録画の運用

  • ライブ監視：監査担当は進行中のセッションを一覧で見て、画面を覗く・一時停止・強制終了ができます（必要な権限が必要）。
  • 録画の検索：アカウント、ターゲット、利用者、期間、入力コマンド等で録画を検索できます。
  • 保管容量：録画はデータ量が大きくなります。保持期間（Safeの保持設定）と容量を規程に合わせて設計します。
  • PTA連携：危険な操作を検知したら自動で一時停止・終了する、といった連携が可能です（第12章）。

6. よくあるトラブル

症状疑うポイント
Connectを押しても何も起きない／RDPがつながらない利用者PC→PSMの3389（またはHTML5 GatewayのHTTPS）がFWで遮断、ロードバランサ設定
PSMには入れるがターゲットに接続できないPSM→ターゲットの通信、ターゲット側のRDP/NLA設定、アカウントのパスワード不一致（→第8章のVerify/Reconcile）
全員が突然接続できなくなったPSMConnect／PSMAdminConnectのパスワード期限切れ・ロック、PSMサービス停止、証明書期限切れ
特定の接続方式だけ起動しない接続コンポーネントの設定、PSMサーバのアプリケーション実行制限（AppLocker等）で対象プログラムが許可されていない
録画が再生できない録画のアップロード失敗（PSM一時領域の容量不足、Vaultとの通信）

振り返り問題（第10章）

Q1. PSMの「分離」により得られる効果として最も適切なのは？

  • 利用者PCがマルウェアに感染していても、資格情報が利用者PCに渡らないため盗まれにくい
  • ターゲットのCPU負荷が下がる
  • パスワード変更が不要になる
  • 承認が不要になる
パスワードはPSM上で使われ、利用者PCに渡りません。

Q2. 利用者のRDPセッションを受け付け、隔離された作業領域に切り替える際に使われる受付用アカウントは？

  • Master
  • Administrator
  • PSMConnect
  • Reconcile Account
PSMConnectです。ライブ監視にはPSMAdminConnectが使われます。

Q3. RDPクライアントが使えない端末から、ブラウザだけでPSMセッションを使う方法は？

  • PSM for SSH
  • HTML5 Gateway
  • PrivateArk Client
  • CPM
HTML5 Gatewayを使うと、ブラウザのタブ内でセッションを開けます。

Q4. ある朝、全利用者がPSM経由で接続できなくなった。最初に確認すべきこととして適切なのは？

  • 個々のターゲットのパスワード
  • Safe名の命名規則
  • 録画の保持期間
  • PSMの内部アカウント（PSMConnect等）の期限切れ・ロックやPSMサービスの状態
全員が同時に失敗する場合は、個別アカウントではなく共通部分（PSMサービス・内部アカウント・証明書・通信）を疑います。
