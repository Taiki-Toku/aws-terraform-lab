CHAPTER 11｜利用・監視

認証・ユーザー管理・ID連携

金庫の鍵をいくら厳重に管理しても、「金庫室に入る人の本人確認」が甘ければ意味がありません。CyberArkへのログインの仕組みと、ユーザー・グループ管理の考え方を学びます。

この章の全体像

ユーザーの種類 → 認証方式（Vault認証・LDAP・RADIUS・SAML・MFA）→ LDAP連携（Directory Mapping）→ Privilege Cloudでの認証（Identity）→ SAML認証の流れ → 設計の勘所

この章のゴール

  • CyberArkで使える主な認証方式と、MFAが必須である理由を説明できる
  • ADグループとVault権限をつなぐ「LDAP連携」の仕組みを説明できる
  • SAMLによるシングルサインオンの流れを説明できる

1. ユーザーの種類

種類概要例
Vault（内部）ユーザーVault内に直接作成されるユーザー組み込みユーザー、緊急用の管理者、コンポーネント用ユーザー
LDAPユーザーActive Directory等のユーザーを連携して利用一般の利用者・管理者（推奨）
コンポーネント・アプリ用ユーザーCPM・PSM・CPなどがVaultへ接続するためのユーザー人は使わない。自動で管理される
人の利用者は原則「LDAPユーザー＋MFA」

Vault内部ユーザーを大量に作ると、入退社・異動のたびに手作業が発生し、消し忘れが起きます。人はADなど既存のID基盤と連携し、Vault内部ユーザーは緊急用などに限定しましょう。

2. 認証方式

方式概要補足
CyberArk（Vault）認証Vaultに保存されたパスワードで認証緊急用ユーザー等
LDAP認証ADのID・パスワードで認証単独ではMFAにならない
RADIUSRADIUSサーバ経由でワンタイムパスワード等と組み合わせMFA製品との連携でよく使われる
PKI（証明書）クライアント証明書・スマートカード高セキュリティ環境
SAMLIdP（Identity・Entra ID・Okta等）で認証し、その結果でログインSSO＋IdP側のMFAを活用できる。現在の主流
MFAは「鍵＋顔認証」の二重ロック

パスワードだけの認証は「鍵だけの玄関」。鍵（パスワード）が盗まれたら誰でも入れます。MFAは「鍵＋顔認証（スマホ承認・生体認証）」です。金庫室の入口であるCyberArkには、必ずMFAを掛けます。

3. LDAP連携（Directory Mapping）

LDAP連携では、ADを「ユーザーの名簿」として使います。Directory Mapping（ディレクトリマッピング）の設定により、「ADのこのグループに所属する人は、Vaultでこういう権限・属性を持つ」というルールを定義します。

ADグループ（例）CyberArkでの扱い
GG_PAM_ADMINSVault Adminsにマッピング（管理機能）
GG_PAM_AUDITORSAuditorsにマッピング（監査）
GG_PAM_INF_USERS などSafeメンバーとして直接登録（第6章）
ADグループ運用のコツ

CyberArk用のADグループは命名規則（例：GG_PAM_で始める）を決め、グループのメンバー変更も申請・承認制にします。ADグループを変更できる人は実質的にCyberArkの権限を変更できるため、ADグループの管理権限自体が重要な統制ポイントになります。

4. Privilege Cloudでの認証（Identity）

Privilege Cloudでは、ISPSSの認証基盤であるIdentity（CyberArk Identity Security Platformのユーザー管理・認証機能）が入口になります。

  • Identityで直接ユーザー管理・MFAを行う方法
  • 社内IdP（Entra ID・Okta等）とSAMLで連携し、社内のSSOとMFAを使う方法
  • オンプレADのユーザー・グループを、Identity Connector経由で利用する方法

どの方式を選ぶかは、既存のID基盤・MFA製品・社内ポリシーで決まります。

6. 設計の勘所

  • MFAは必須：特にVault管理者・Safe管理者・監査担当など権限の強い人から優先します。
  • IdPが止まったときの手段：IdP障害でCyberArkに誰も入れないと、障害対応に必要な特権も使えません。緊急用の認証経路（ブレークグラス）を設計・文書化しておきます。
  • 退職・異動の自動反映：IdP・ADの無効化でCyberArkも使えなくなることを確認します。
  • 人の特権IDとログインIDの分離：普段のメール用IDとは別に、管理者用ID（例：adm-a.takahashi）を使う組織もあります。

振り返り問題（第11章）

Q1. SAML認証で、CyberArkがIdPから受け取るものは？

  • 利用者のADパスワード
  • 電子署名付きの認証結果（SAMLアサーション）
  • ターゲットのパスワード
  • 録画ファイル
CyberArkは署名付きの認証結果を検証するだけで、ADパスワードは受け取りません。

Q2. ADのグループとVaultの権限・属性を結び付ける設定は？

  • Master Policy
  • Connection Component
  • Reconcile Account
  • Directory Mapping（LDAP連携）
Directory Mappingで、ADグループに応じたVault上の扱いを定義します。

Q3. IdPと連携する際に必ず検討すべきことは？

  • IdP障害時でもCyberArkに入れる緊急用の認証経路
  • 録画の解像度
  • Safe名の長さ
  • CPMの変更間隔
IdPに依存しきると、IdP障害時に特権が一切使えなくなります。

Q4. 人の利用者アカウントの推奨的な管理方法は？

  • Vault内部ユーザーを人数分作る
  • 全員でAdministratorを共有する
  • AD等のID基盤と連携し、MFAを掛ける
  • Masterユーザーを配布する
既存のID基盤と連携することで入退社・異動が自動で反映され、MFAで本人確認を強化できます。
