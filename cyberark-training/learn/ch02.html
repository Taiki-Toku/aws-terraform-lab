CHAPTER 02｜基礎

CyberArk製品群の全体像

CyberArkは「PAMの会社」から「アイデンティティセキュリティの会社」へと広がりました。まずは製品の地図を頭に入れ、自分が担当する製品がどこにあるかを把握します。

この章の全体像

会社の動向（買収・新ブランド）→ 製品マップ → 提供形態（Self-Hosted / SaaS）→ 製品名の変遷 → 新人が最初に触る範囲

この章のゴール

  • 主要製品（PAM Self-Hosted、Privilege Cloud、SIA、SCA、EPM、Secrets Manager、Secrets Hub、Workforce Identity）が何を守るかを1行で言える
  • 旧製品名と新製品名の対応を知り、古い資料を読んでも混乱しない
  • 2026年の会社動向（Palo Alto Networksによる買収、Idiraブランド）を正しく説明できる

2. 製品マップ

CyberArkの製品群は「誰の（どんな）アイデンティティを」「どこで」守るかで整理すると覚えやすくなります。

製品一言でいうと提供形態詳しく
PAM Self-Hosted特権IDの金庫・自動変更・セッション録画を自社環境に構築オンプレ／自社管理のクラウド第3〜12章
Privilege Cloud上記をSaaSで利用。Vault等の運用はCyberArkSaaS＋顧客側コネクタ第5章
Secure Infrastructure Access（SIA）サーバ・DB・Kubernetesに、その場限りの権限で接続（旧 Dynamic Privileged Access）SaaS第14章
Secure Cloud Access（SCA）AWS/Azure/GCPの管理画面への期間限定の権限付与SaaS第14章
Endpoint Privilege Manager（EPM）PCやサーバのローカル管理者権限を取り上げ、必要なアプリだけ昇格SaaS＋エージェント第14章

製品群は「警備会社のサービスメニュー」

PAMは本社金庫室の警備、EPMは各社員の机の引き出しの鍵管理、Remote Accessは業者の入館受付、Secrets Managerは工場の自動ロボットが使う鍵の管理、Workforce Identityは社員証ゲートです。同じ警備会社なので、受付（認証）や監視カメラの記録（監査）は共通の仕組みにまとまっています。これがISPSS（共通基盤）です。

3. 提供形態：Self-Hosted と SaaS

🏢 Self-Hosted（自社構築）

  • Vault・PVWA・CPM・PSMなどを自社で構築・運用
  • バージョンアップ・バックアップ・DRも自社の責任
  • 閉域網・厳格な規制要件の組織で採用されることが多い

☁ SaaS（Privilege Cloud ほか）

  • Vault等の中核をCyberArkが運用
  • 顧客側はコネクタ（CPM・PSM等）だけを運用
  • 機能追加が早く、ISPSS上の他SaaS製品と統合しやすい

詳しい比較と選び方は第5章で扱います。

確認方法

名称変更の一次情報はCyberArk公式の「Product Name Updates」ページです。Conjur→Secrets Managerの改称は同ページで確認済み。その他は複数の公開資料で一致を確認しています（出典ページ）。

5. 新人が最初に触る範囲

多くの現場では、まずPAM（Self-HostedまたはPrivilege Cloud）の運用から担当します。本教材の第3〜12章はこのPAMを中心に構成されています。SIAやSecrets Managerなどは、PAMの考え方（Safe・ポリシー・監査）を理解してから学ぶと理解が速くなります。

お客様との会話で困らないために

お客様が「CyberArk入ってます」と言ったら、まず「Self-HostedとPrivilege Cloudのどちらですか？バージョンは？」と確認しましょう。前提がまるで違うためです。

振り返り問題（第2章）

Q1. 保守委託先がVPNを使わずに安全に特権アクセスするための製品は？

  • Endpoint Privilege Manager
  • Secrets Hub
  • Remote Access
  • Credential Provider
Remote Accessです（旧Aleroの系譜）。EPMは端末のローカル管理者権限の制御、Secrets Hubはクラウドのシークレットストア同期、CPはアプリ向けです。

Q2. 「Conjur Enterprise」の現在の名称は？

  • CyberArk Secrets Manager, Self-Hosted
  • CyberArk Secrets Hub
  • Privilege Cloud
  • Workforce Identity
Conjur EnterpriseはSecrets Manager, Self-Hosted、Conjur CloudはSecrets Manager, SaaSに改称されました。

Q3. Privilege Cloudの説明として正しいものは？

  • Vaultを顧客が自社データセンターで運用する
  • Vault等の中核をCyberArkが運用し、顧客はコネクタを運用する
  • エンドポイントのローカル管理者権限を管理する製品である
  • アプリ専用で、人の特権アクセスは扱えない
Privilege CloudはPAMのSaaS版で、顧客側にはCPMやPSMを載せたコネクタを置きます。

  • CyberArkがPalo Alto Networksを買収した

  • CyberArkはPAM製品から撤退した
  • Palo Alto NetworksによるCyberArk買収が2026年2月に完了し、5月にIdiraブランドが発表された
買い手はPalo Alto Networksです。買収完了は2026年2月11日、Idiraブランドの発表は2026年5月です。
