CHAPTER 16｜ハンズオン

ハンズオン演習（検証環境）

読んで理解したことを、実際に手を動かして確かめます。登録 → 接続 → 録画確認 → 承認 → 障害を起こして直す、までを一人でできるようになるのがこの章の目標です。

この章の全体像

演習のルール → 検証環境の構成 → 演習1〜8（画面ツアー、Safe作成、アカウント登録、PSM接続と録画、二重承認、パスワード不一致からの復旧、CPMエラーの切り分け、REST API）→ 後片付け

この章のゴール

  • Safe作成からアカウント登録・検証・変更までを手順書なしで実施できる
  • PSM経由で接続し、録画・操作ログから自分の操作を探し出せる
  • パスワード不一致やCPMエラーを意図的に起こし、原因を特定して復旧できる
目安 6〜8時間（2日に分けて実施推奨）前提：第1〜15章検証環境必須
演習のルール（必ず守る）
  • 本番環境では絶対に実施しない。演習はすべて検証環境（lab.hikari.example）で行う
  • 演習で意図的にパスワードを不一致にするのは、演習用に用意したアカウントだけ（ドメイン管理者などは使わない）
  • 講師（山本さん）の指示なく、Master Policy・既存プラットフォーム・既存Safeを変更しない
  • 終わったら必ず「後片付け」を行い、講師に完了報告する
画面名・メニュー名について

PVWA（Self-Hosted）とPrivilege Cloudでは画面構成が異なり、バージョンによってもメニュー名が変わります。本章では操作を「何をするか」で書いています。迷ったら講師に確認するか、公式ドキュメントの該当バージョンを参照してください。各演習の画面キャプチャ枠には、講師が自社の検証環境の画面を差し込めます。

検証環境の構成（架空）

演習用アカウント（例）ターゲット用途
labroot-XX（XXは受講者番号）lab-lnx01登録・接続・不一致演習用（sudo可能なローカルユーザー）
labops-XXlab-lnx01Logon Account用の一般ユーザー
labadmin-XXlab-win01Windowsローカル管理者の演習用
svc_lab_reconcilelab-lnx01 / lab-win01調整（Reconcile）用。講師が事前に登録・管理

講師は演習前に、受講者ごとの演習用アカウント・ADグループ（例：GG_LAB_USERS_XX）と初期パスワードを用意し、紙または別経路で渡してください。

演習1：画面ツアー（30分）

目的：どこに何があるかを把握する（第3章）。

  • 検証環境のPVWA（https://lab-pvwa01.lab.hikari.example/PasswordVault）に自分のIDとMFAでログインした
  • アカウント一覧・Safe一覧・録画（監視）画面・申請（承認）画面の場所を確認した
  • 管理者でないと見えないメニューがあることを確認した（権限で画面が変わる）
  • 自分のログイン操作が監査ログ（アクティビティ）に記録されていることを確認した

演習2：Safeの作成とメンバー追加（40分）

目的：命名規則に沿ったSafeを作り、役割に合った権限を付ける（第6章）。※Safe作成権限は講師が一時的に付与します。

  • 命名規則に沿ってSafe LAB-STG-INF-LNX-XX を作成し、説明欄にオーナー（自分の名前）を記入した
  • 担当CPMとして lab-cpm01 が割り当てられていることを確認した
  • 自分の演習用ADグループ GG_LAB_USERS_XX に List＋Use だけを付与した
  • 講師（承認者役）を List＋Authorize account requests で追加した
  • メンバー追加の操作が監査ログに残っていることを確認した
振り返り

自分自身に Retrieve や Manage Safe members を付けたくなったら、それは職務分掌（SoD）違反のサインです。講師に理由を説明できるか考えましょう。

演習3：Linuxアカウントの登録・検証・変更（60分）

目的：Logon Account付きでrootに相当するアカウントを登録し、CPMで管理下に入れる（第7・8章）。

  • labops-XX（Logon Account）を先に登録した
  • labroot-XX を、講師指定のLinux用プラットフォーム（例：LAB-Unix-SSH）とSafe LAB-STG-INF-LNX-XX を指定して登録した
  • labroot-XX に Logon Account（labops-XX）と Reconcile Account（svc_lab_reconcile）を関連付けた
  • Verify（検証）を実行して成功した
  • Change（変更）を実行し、成功した。旧パスワードで直接SSHできなくなったことを講師と確認した
  • アカウントの履歴（バージョン）に変更が記録されていることを確認した

演習4：PSM経由の接続と録画の確認（45分）

目的：パスワードを見ずに接続し、自分の操作を録画から探す（第10章）。

  • PVWAから labroot-XX で「Connect」し、パスワードを見ずに lab-lnx01 にログインできた
  • セッション内で hostname、id、ls /etc を実行してから切断した
  • SSHクライアントから PSM for SSH 経由でも接続できた（書式は講師が配布する手順に従う）
  • 録画一覧から自分のセッションを探し、再生できた
  • 操作ログ（コマンド）で id を検索し、録画の該当箇所へジャンプできた

演習5：二重承認ワークフロー（2人1組・40分）

目的：申請者・承認者の両方を体験する（第9章）。講師が演習用プラットフォームに二重承認の例外を設定済みとします。

  • 申請者として、理由（例：LAB-CHG-0001）と時間帯を入力して利用申請した
  • 承認前は接続できないことを確認した
  • 承認者役として、相手の申請内容を確認して承認（または理由を付けて却下）した
  • 承認後に接続でき、申請・承認・接続が監査ログで1本の線としてつながっていることを確認した

演習6：パスワード不一致を起こして復旧する（障害演習・45分）

目的：Verify失敗 → 原因特定 → Reconcile の流れを体で覚える（第8章）。

  • Verify失敗のエラーメッセージを読み、「認証失敗」であることを特定した
  • 影響範囲（自分のアカウントだけか）を確認した
  • Reconcileで同期を回復し、Verifyが成功した
  • 事象・原因・対応・再発防止の4点で講師に報告した

演習7：CPMエラーの切り分け（45分）

目的：エラーの「段階」を見極める（第8章）。講師が次のいずれかの障害を仕込みます。受講者は原因を当ててください。

講師が仕込む障害（例）受講者が見つけるべき手がかり
A：lab-lnx01 側でSSHを一時停止接続段階のエラー（タイムアウト・接続拒否）
B：Logon Account の関連付けを外すログオン段階のエラー（rootへの直接ログイン拒否）
C：演習用プラットフォームの使用禁止文字から、ターゲットが受け付けない記号を外す変更段階のエラー（ターゲットが新パスワードを拒否）
  • PVWAのエラーメッセージから、失敗した段階（接続／ログオン／変更／検証）を特定した
  • CPMサーバのログ（講師が閲覧方法を案内）で裏付けを取った
  • 原因を修正（または講師に修正依頼）し、再実行で成功した

演習8（発展）：REST APIで自分のアカウントを取得する（30分）

目的：自動化の入口を体験する（第15章）。エンドポイント・認証方式はバージョンの公式APIリファレンスで確認してください。

# PowerShell の例（検証環境・概念例）
$base = "https://lab-pvwa01.lab.hikari.example/PasswordVault"
$cred = Get-Credential   # 自分の検証用ID（パスワードをスクリプトに書かない）
$body = @{ username = $cred.UserName; password = $cred.GetNetworkCredential().Password } | ConvertTo-Json
$token = Invoke-RestMethod -Method Post -Uri "$base/API/auth/LDAP/Logon" -Body $body -ContentType "application/json"
Invoke-RestMethod -Method Get -Uri "$base/API/Accounts?search=labroot" -Headers @{ Authorization = $token } |
  Select-Object -ExpandProperty value | Select-Object name, address, userName, safeName
  • APIで自分のSafeにあるアカウントだけが返ってくる（権限がAPIにも効いている）ことを確認した
  • APIによるログオン・取得が監査ログに記録されていることを確認した
  • ログオフ（トークンの破棄）を行った

後片付け

  • 演習で使ったセッションをすべて切断した
  • 講師の指示に従い、演習用アカウントを削除（または講師に引き渡し）した
  • 一時的に付与されたSafe作成権限などが外されたことを講師と確認した
  • 手元のメモ・スクリーンショットにパスワードが残っていないことを確認した

チェック状態はこのブラウザに保存され、成績・学習記録から講師へ提出できます。

振り返り問題（第16章）

Q1. 障害演習で意図的にパスワード不一致を起こしてよいアカウントは？

  • 本番のドメイン管理者
  • 検証環境のReconcile Account
  • 検証環境に用意された自分の演習用アカウント
  • 講師のPVWAログインアカウント
演習は検証環境の、演習用に用意されたアカウントだけで行います。Reconcile Accountを壊すと調整自体ができなくなります。

Q2. APIで取得できたアカウントが自分のSafeのものだけだった。理由として正しいものは？

  • APIにも画面と同じSafe権限が適用されるから
  • APIは常に1件しか返さないから
  • APIは管理者専用だから
  • 検証環境にアカウントが1件しかないから
APIは画面と同じ権限モデル（Safe権限）で動作し、操作は監査ログに残ります。

Q3. 演習7で「rootへの直接ログインが拒否された」エラーが出た。最も疑わしい原因は？

  • SSHサービスの停止
  • Vaultの停止
  • 使用禁止文字の設定
  • Logon Accountの関連付けが外れている
ログオン段階のエラーです。rootへの直接SSHが禁止された環境では、Logon Accountが必要です。
